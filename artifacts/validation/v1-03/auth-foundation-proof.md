# V1-03 authorisation foundation

The service foundation implements a two-phase lifecycle. Phase 1 claims the opaque attempt and transactionally stores read-only credentials in Vault with durable `callback_received` state; capture failure invokes an idempotent abort and no provider request occurs before acknowledgement. Phase 2 preserves captured credentials for allowlisted transient errors, removes them for terminal identity/authentication errors, and atomically establishes/audits/consumes success. Attempts use a maximum 15-minute TTL, fixed-purpose expiry cleanup, and replacement cleanup under a Connection lock. Public Express route wiring remains outside this foundation boundary.
